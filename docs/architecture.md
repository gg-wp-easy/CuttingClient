# TypeScript и Feature-Sliced Design

Клиент использует React 19, TypeScript в strict-режиме и сборку на Vite.
Все исходники приложения и тесты в `src` — `.ts` / `.tsx`.
Главный процесс Electron находится в `electron/main.ts` и собирается отдельно:
он выполняется в Node.js, поэтому не входит в FSD-слои интерфейса.

## Слои

| Слой | Ответственность |
| --- | --- |
| `app` | Запуск React, маршрутизация по hash, глобальные стили |
| `pages/linear-cut` | Состояние и восстановление заказа, форма линейного раскроя, сборка страницы |
| `pages/sheet-cut` | Форма и сборка страницы двумерного раскроя |
| `widgets/app-header` | Навигация и команды настольного приложения |
| `widgets/linear-cut-result` | Сводка, таблица и диаграммы результата |
| `features/calculate-cutting` | Запуск расчёта, ошибки, отмена запросов, сохранение параметров результата |
| `features/cutting-workbook` | Импорт заказов, экспорт результатов в Excel и печать |
| `entities/cutting` | Типы предметной области, проверка параметров, API раскроя, диаграммы |
| `shared/api` | HTTP-транспорт, базовый URL службы |
| `shared/lib` | Адаптер Electron, группировка строк и форматирование |
| `shared/ui` | Общие поля, редактируемая таблица и состояния интерфейса |

Сегменты внутри слайсов: `ui`, `model`, `api`, `lib`. Страница владеет своим
состоянием формы; компоненты таблиц управляются через props. Слой Shared
не содержит бизнес-типов раскроя. Сценарии общие для обеих страниц вынесены
в Features. Неиспользуемые слои и промежуточные абстракции не создаются.

Импорты идут только вниз: `app → pages → widgets → features → entities → shared`.
Слайсы одного слоя не импортируют друг друга. Между слайсами используются
только публичные `index.ts`; внутри слайса — относительные импорты.
`app` и `shared` состоят из сегментов без слайсов. Абсолютные импорты от `src`
настроены через `baseUrl` TypeScript. Проверка `npm run check:fsd` разбирает AST
импортов и экспортов, включая динамические импорты, и проверяет эти границы.

Правила основаны на [официальном описании FSD](https://fsd.how/docs/get-started/overview/).

## Контракты и совместимость

`entities/cutting/model/types.ts` описывает запросы и ответы Python-службы.
Ответы HTTP и сохранённые данные проверяются при чтении из внешней среды.
Ширина пропила допускает дробное значение. Размеры деталей и исходного материала
остаются целыми, как требует текущая модель сервера.

Результат хранится вместе с отправленным запросом: изменение формы не меняет
подписи и Excel-экспорт предыдущего расчёта. Новый расчёт отменяет предыдущий;
при уходе со страницы запрос также отменяется. Группировка учитывает порядок
столбцов и исходную длину материала.

Hash-маршруты `#/` и `#/double` работают и через HTTP, и через `file://` в Electron.
Линейный заказ сохраняется в localStorage; при первом запуске поддерживается
импорт старого массива из `local_data.json` через существующий IPC-протокол.
Новый локальный черновик имеет приоритет перед старым файлом. Подписки IPC
удаляются по конкретному обработчику, а не через removeAllListeners.

Импорт линейного заказа: столбцы «Длина», «Количество»; двумерного:
«Длина», «Ширина», «Количество». Заголовок необязателен. Экспорт результатов —
отдельный отчёт, а не формат импорта заказа.

Текущий двумерный сервер возвращает размеры и количества, но не координаты.
Клиент показывает состав ответа и эскизы деталей, не выдавая их за размещение
на листе. Алгоритмы серверной части при этой миграции не менялись.

## Проверки

- `npm run typecheck` — строгая проверка интерфейса и Electron.
- `npm run check:fsd` — проверка направлений импортов и публичных API.
- `npm test -- --runInBand` — тесты компонентов, контрактов и пользовательских сценариев.
- `npm run build` — проверки, production-сборка React и компиляция Electron.

Тесты находятся рядом с модулями, которыми владеют. Интеграционные тесты
в `app` проверяют обе страницы, одиночный/множественный материал, повтор расчёта
после ошибки и неизменность параметров уже полученного результата.
